# Good / Motto — フロントエンド

[Issue #3](https://github.com/Tamach1Q/good-motto/issues/3) のスマホ向けWebアプリです。React / TypeScript / Viteで実装しています。

**Phase 1（モック）向けの実装です。実バックエンドとの認証・DB保存の結合テストは未実施です。**
APIの参照元は [API契約 v1](https://github.com/Tamach1Q/good-motto/blob/main/docs/api/contract-v1.md)。このコードはAPIサーバー・AI・Slack通知・M5Stackを実装しません。

## 起動

Node.js 22.12以上（検証環境：24.18）を使用してください。

```sh
cd frontend
npm ci
npm run dev
```

表示されるローカルURLを開きます。既定は **デモモード** です。実データの外部送信・保存・Slack検索はありません。画面上部にもデモと表示します。

```sh
npm test
npm run build
npm run preview
```

スマホ実機から同じWi-Fiの開発PCに接続する場合は、`npm run dev -- --host 0.0.0.0` で起動し、表示されるNetwork URLを開きます。開発サーバーをインターネットに公開しないでください。

## デモ操作

### 人物を対象にする

1. 「話している途中で遮られた。最後まで聞いてほしかった。」と入力。
2. AI分類への同意チェックを入れ、「内容を確認する」。デモではAI通信はしません。
3. 確認画面でGood / Mottoを変更できます。本文も編集できます。
4. 「対象を選ぶ」→「人物」→「田」を入力。300ms後に候補が出ます。
5. 同じ名前「田中 太郎」が2件あります。識別IDを見て片方を選びます。
6. 対象を確認して「投稿を試す」。保存・通知をしていない完了画面が出ます。

### 場所を対象にする

1. 「共用キッチンが汚くてイライラした」と入力して確認へ。
2. モックはAPI契約と同じ `motto / place / kitchen / 共用キッチン` を提案します。
3. 提案だけでは対象を確定しません。「対象を選ぶ」→「場所」→「共用キッチン」を選びます。
4. 最終確認して投稿を試します。

### エラー等

画面上部の「デモ」を開くと、次の失敗を選んで再現できます。

- 分析エラー / 分析不能：本文を残して入力画面へ戻り、投稿はしません。
- 人物検索エラー / 場所取得エラー：検索画面でエラーと再試行を表示。
- 投稿エラー：確認画面と本文を残す。
- 候補なし：通常モードで「髙橋」を検索。

失敗を解除するには「通常」に戻します。デモ用設定は実APIモードでは表示しません。

## 実APIへ切り替える

`.env.example` を `.env.local` にコピーして設定し、開発サーバーを再起動します。

```dotenv
VITE_API_MODE=live
VITE_API_BASE_URL=
VITE_LOGIN_URL=
```

- `VITE_API_BASE_URL` は **`/api/v1` を含まない** オリジン（例 `https://api.example.test`）。空なら同一オリジン。
- ローカル開発では `/api` をViteが `http://127.0.0.1:8787` に中継します。必要なら `vite.config.ts` を変更。
- 本番では `dist/` をWorkers Static Assets等で配信し、`/api/v1/*` はバックエンドへルーティング。
- Cookie認証に対応するため通信は `credentials: include`。ログイン先は `VITE_LOGIN_URL` に `/api/v1/auth/slack/login` を設定します。未設定では案内のみ表示。
- 認証仕様は `docs/auth/slack-oidc-v1.md` で確定しています。この実装ではセッション確認・同意設定・ログアウトの画面接続は未対応です。**ログイン済みであると仮定する偽の認証機能はありません。** 401/403はエラー表示します。
- 確定した認証仕様に従い、WebとAPIは同一オリジンで配信してください。任意の別オリジンでの本番運用は想定しません。
- `VITE_` の値はブラウザから見えます。GeminiキーやSlackトークンを設定しないでください。

## 入力の扱い

- 本文は同じタブの `sessionStorage` に下書き保存します。リロード後に復元し、投稿成功・空欄時に削除します。対象者は保存しません。
- 同一オリジンのスクリプトは下書きを読み取れるため、共有端末等では運用を確認してください。
- 本文の上限5,000文字は暫定のフロント制限。バックエンドと合意が必要です。
- 人物IDはAIの提案だけで確定せず、候補を選ぶまで投稿ボタンを無効にします。
- iPhoneのキーボードは端末本来のものを使用します。Figmaの英字キーボード画像は組み込みません。
- 文字列はReactで描画し、入力をHTMLとして挿入しません。本文・人物名をログに出しません。
