## 受け渡す範囲

この `frontend/` をリポジトリ直下に配置して使用してください。`npm ci` → `npm test` → `npm run build`。既存のバックエンドとは独立しています。本PRはモック投稿フローを共有するためのものです。

## HTTP通信

| 操作 | リクエスト | 使用する結果 |
| --- | --- | --- |
| 分析 | `POST /api/v1/posts/analyze`、`{text}` | `sentiment`, `target_type`, `target_id`, `target_label` |
| 人物検索 | `GET /api/v1/people?query=...` | `{people:[{id,name}]}` |
| 場所候補 | `GET /api/v1/places` | `{places:[{id,name}]}` |
| 投稿 | `POST /api/v1/posts` | `{post_id,status:"created"}` |

投稿本文は次の4項目だけです。投稿者ID・日時は追加せず、サーバー側に任せます。

```json
{"text":"共用キッチンが汚くてイライラした","sentiment":"motto","target_type":"place","target_id":"kitchen"}
```

共通エラー `{error:{code,message}}`、400/401/403/429/5xx、非JSON・不正な成功レスポンス、ネットワーク失敗、20秒のタイムアウトを処理します。投稿は自動再送しません。画面上の連打はロックしますが、タイムアウト後の再送まで冪等にはできません。必要ならAPI担当と別途合意してください。

## Slack検索：合意が必要な点

- 文字確定後、1文字から300ms待って人物検索。IME変換中は検索しません。
- 検索語変更・画面離脱で前のリクエストを中止。古い結果が遅れて返っても表示しません。
- 対象は `people[].id` で保存。これをSlackユーザーIDへ対応付けるのはサーバー側です。
- **契約v1は `id` と `name` だけです。** モックはこの形式を守ります。同姓同名では識別IDを表示しますが、IDだけで本人を見分けにくい場合は使い始める前に改善が必要です。
- Figmaのユーザー名・写真に対応するには、`username` / `avatar_url` / `workspace_label` のような追加項目の合意が必要です。フロントはこれらがあれば表示できますが、**契約書は変更していません。必須にしていません。** Issue #4担当との合意後に契約を更新してください。
- Slackトークンをフロントへ渡さないでください。Slackメンバー取得・権限・公開対象の絞り込み・検索はバックエンドの責任範囲です。

## 分析・確認

- 分析は提案。Good / Mottoは確認画面で修正できます。
- `target_type=unknown` や対象IDが不明でも、ユーザーが実在する候補を選べます。
- **分析自体が失敗した場合は投稿させません。** ユーザーを入力画面へ戻して本文を維持します。
- AIが人物IDを返しても本人選択を省略しません。場所も一覧から明示選択します。
- 最終画面の投稿ボタンを押した時だけ保存します。人物向け通知は週次処理で、原文の即時送信ではありません。

## 認証・同意：Phase 2で要対応

認証は [Slack OIDC認証設計](../docs/auth/slack-oidc-v1.md) で確定済みです。現在のコードはCookie付きHTTP通信とログインへのリンクのみを備えています。以下はこのPRに含めていません。

1. `GET /api/v1/me` による本人・ログイン状態の取得と画面の分岐。
2. `PATCH /api/v1/me/preferences` による利用同意の保存とDM受信設定（初期false・撤回可）。今のチェックボックスは分析前のローカル同意であり、サーバーの利用同意記録の代わりにはなりません。
3. `POST /api/v1/auth/logout` によるログアウト。
4. 401/403からの復帰、実OAuth、実DB保存の結合検証。

認証開始リンクは `VITE_LOGIN_URL=/api/v1/auth/slack/login` で設定できます。サーバーのCookieはHttpOnlyで、フロントにトークンを持たせません。確定仕様どおり同一オリジンで配信してください。`VITE_API_BASE_URL` の変更は開発用の接続調整を目的とします。
